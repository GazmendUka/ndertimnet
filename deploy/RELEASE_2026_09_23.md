## Rollback

Suspend the two billing cron jobs first if they have been activated. Restore the
previous backend deploy `dep-daegehgn74is73dnr4g0` (commit
`4a196bd0b600c012407f29a138be88246e6ee612`) and frontend deploy
`dep-dajc0op5efls739jisag` (commit `87042d87873d9aabfd586b67d38d490d0cd184e6`).
Do not reverse migrations automatically: they add tables/fields and preserve
accepted-version references. Reversing them would lose new billing records.
Rolling back code does not reverse workflow changes or remove new records.
If a data restore is necessary, restore Render's pre-release backup/PITR into a
separate database, validate it, and account for post-release writes before switching.
Do not overwrite the live database as a routine application rollback.
